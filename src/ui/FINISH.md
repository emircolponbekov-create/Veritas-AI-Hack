# Оставшиеся шаги до сдачи

## 1. Ручная проверка — 5–10 минут

Сервер дизайна запускался на http://127.0.0.1:8503.
Если он завершился, из корня проекта:

```powershell
.\src\ui\.venv\Scripts\python.exe -m streamlit run src/ui/app.py --server.address 127.0.0.1 --server.port 8503 --browser.gatherUsageStats false
```

Проверь Surry, Calvert Cliffs, две системы Brunswick, ограниченную
систему, месяц без оценки и узкое окно. Три вкладки: история,
качество модели и источники. Метрики не должны оставаться от другой системы.

## 2. Один завершающий Work — материалы и документы

Готовый промпт:

```text
Подготовь проект Nuclear Water & Climate Lab к сдаче одним проходом.
Прочитай актуальные инструкции, правила хакатона, контракт,
MODEL/UI-handoff и реальные артефакты. Не переобучай модели.

1. Создай в submission/ описание примерно на страницу на английском,
сценарий демо до двух минут для двух участников, credits и чек-лист.
Используй фактические метрики: ожидаются 17 оценённых систем,
у 4 Ridge лучше лучшего baseline; перепроверь по файлам.
Честно объясни отрицательные результаты, период и ограничения.
Не выдумывай вклад участников, персональные данные или проверки.
Недостающие сведения обозначь для заполнения.

2. Проверь существующий Colab/IPYNB: есть ли сохранённые выходы.
Если их нет, подготовь показ проверенных артефактов с явной
подписью их происхождения и инструкцию сохранения в Colab.
Без нового подбора параметров и молчаливой замены результатов.

3. Ты назначен последовательно актуализировать README, TASKS,
SOURCES и LOG по завершённым работам. Историю сохраняй.
Отдельно укажи фактически выполненную ручную проверку браузера;
если её подтверждения нет, оставь это незавершённым.

4. Проверь пути и ссылки, которые доступны локально. Подготовь
список конкретных файлов для передачи жюри и инструкцию запуска.
Не включай .venv, кэш, локальные логи и лишние персональные данные.
Не делай вид, что localhost доступен жюри.

Не добавляй новые функции. Не публикуй, не меняй права доступа,
не выполняй Git-операции записи и не отправляй заявку.
В финале дай только список готового, файлы и оставшиеся ручные шаги.
```

## 3. Действия команды

- Оба участника читают объяснение кода и репетируют демо.
- Заполняют реальные сведения и вклад каждого.
- По отдельному явному поручению готовят доступную жюри ссылку
  на GitHub или Colab и проверяют её без авторизации.
- Один участник отправляет заявку по правилам хакатона.

Видео по локальному изложению правил необязательно. Новые станции,
улучшение моделей по уже просмотренному test и Fuel сейчас не входят
в завершающий проход.
